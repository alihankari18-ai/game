# Ортақ қала: экрандар, технология және бірінші прототип

Нұсқа 0.1. Күні: 2026-11-09. Негізі: дизайн/әдіснама 0.6 және compact_0.1 сценарийі. Бұл қосымша технология таңдауын нақтылайды және іске асырылған автобус эпизодын құжаттайды. Қалған эпизодтардың келісілген сценарийін өзгертпейді.

## 1. Жобаның қазіргі мәртебесі

Төрт эпизодтың дизайны бар. Бірінші автобус эпизоды құрастырылды, автоматты тесттер орындалды. Нақты адамдармен пилот және негізгі жинау әлі жүргізілген жоқ. Барлық осы жинақ деректері — dev, зерттеу таңдамына кірмейді. 12–15 минут — төрт эпизодқа арналған, әлі өлшенбеген мақсат.

25 әдебиеттің пайдаланушы растаған DOI мәртебесі өзгермейді. Төмендегі технология құжаттары сол 25 әлеуметтанулық еңбектің орнына саналмайды. Нақты бет/дәйексөздер мен механикаға қатысты тұжырымдарды сәйкестендіру бұрынғы әдіснамалық картада жалғасады.

## 2. Технологияны салыстыру

Бағалау өлшемдері: браузерден ашылу; телефондағы мәтін/форма; қала көрінісі; нақты әрекетті тіркеу; шағын команданың жөндеу мүмкіндігі. Бағалар — жобалық инженерлік пайым, өлшенген бенчмарк емес.

| Нұсқа | Осы ойынға сәйкестігі | Журнал жүргізу | Негізгі шығын/шектеу | Шешім |
|---|---|---|---|---|
| Phaser 3 + TypeScript + HTML интерфейс | 2D изометриялық аудан, таңдау панельдері, браузер және DOM формалар | Өз серверімізге құрылымды сұраулар, серверлік тексеру | Көрініс пен HTML күйін келісу керек; сервер бөлек қажет | Таңдалды |
| Godot + веб-экспорт | Қала мен анимацияға бай ойын жасауға жарамды; редактор бар | HTTP арқылы серверге журнал жіберу бөлек жасалады | Қысқа мәтіндік сценарий үшін веб-интерфейс/экспортты қосымша бейімдеу қажет | Кейін күрделі кеңістіктік ойын керек болса қарастыру |
| React + Three.js / React Three Fiber | Үшөлшемді қала мен DOM интерфейсін біріктіруге болады | Веб-серверге сұрауларды өзіміз құрамыз | 3D камера, модельдер және React/Three экожүйесін басқару көлемі артады | Қазіргі төрт қысқа эпизодқа артық күрделілік |

## 3. Экрандар және өту ережесі

| Экран | Көрінетін мазмұн/әрекет | Келесі күй және тіркеу |
|---|---|---|
| Кіріспе және dev келісімі | Симуляция, сақталатын дерек, жүктеу/жою; екі бос checkbox | Екеуі расталса сессия; бас тартса журнал жоқ |
| Кейіпкерлер | Төрт өмірбаян, артықшылық/шектеу, жеке мақсат | Таңдау бекітіледі; condition бір рет кездейсоқ тағайындалады |
| Үйрету | Уақыт бірлігі, қатыспау мүмкіндігі, аялдаманы ашу | bus сценарийі басталады; ресурс бір рет беріледі |
| Аялдама және чат | №18 өзгерісі; baseline қолдау/ақпарат/пікірсіз | Үшеуі де бірдей жауап экранына өтеді |
| Әкімдік жауабы | actionable немесе generic ортаңғы абзац | Экран көрсетілгеннен кейін feedback_shown |
| Таңдау панелі | Материал, жеке ұсыныс, жауапты қайта оқу, аяқтау | Барлық нұсқа екі топта бірдей |
| Материалдар | Қазіргі/ұсынылған бағыт сызбасы; нақты минуттық кесте жоқ екені | Бірінші ашу ғана бейіндік уақыт алады; қайта ашу тегін |
| Ұсыныс | Екі бос таңдау, автоматты preview, құн | Жоба сақталады; жібергенде ғана completion және шығын |
| Эпизод нәтижесі | Нақты орындалған әрекет, қаралу мәртебесі | bus аяқталады, primary бекітіледі; clarity 1–5 немесе null |
| Прототип қорытындысы | Автобус қана аяқталғаны, түсіндірме, экспорт | prototype_complete=true; full_game_complete=false |

Әкімдік хатындағы жіберуші, уақыт, стиль, батырмалар және құн бірдей. Ойыншының бастапқы baseline жауабы condition-ды өзгертпейді. Барлық кейіпкер өзіне берілген ресурспен негізгі ұсынысты жібере алады. Шешімдер алдын ала таңдалмайды.

Материалдардағы ескі/жаңа кесте әзірге нақты минут сандарын ойдан қоспай, бағыттардың сапалық айырмасын береді. Жоба бекітілмеген; жаяу жүрудің шамамен 12 минуты ғана сценарийдегі бекітілген факт ретінде қалады.

Қала картада көрсетіледі; пернетақта пайдаланушысы картадағы аялдамаға балама HTML батырмасымен өте алады. Кейіпкерлердің суреттері — уақытша векторлық портреттер; есімдері мен келісілген киім белгілері сақталған.

## 4. Сақтау, қайта қосылу және дерекке қолжетімділік

Сервер ережелердің негізгі көзі: ресурсты, реттілікті, condition мен аяқталуды браузер өзі бекітпейді. Әр қабылданған пәрмен бір SQLite транзакциясында күйді, оқиғаларды және қайталануды танитын request_id жазбасын сақтайды. Сол request_id қайта келсе, жаңа аяқтау/шығын жасалмайды.

Келісімді құру сұрауы да тұрақты кездейсоқ кілтпен қайталана алады. Жауап жоғалса екінші қатысушы жасалмайды. Кілт браузерде сақталады, серверде тек хэші сақталады; экспортта кілт жоқ. Басқа терезедегі ескі күймен келген өзгеріс қабылданбайды.

Желі қатесінде келесі әрекет тоқтатылады; pending пәрмен браузерде қалады. Қайта қосылғанда сол пәрмен қайталанады. Таб сөнуі техникалық аяқтау болып саналмайды. elapsed_ms сервердегі сессия басынан есептеледі, фондағы және жабық тұрған аралықты қамтиды; active_decision_ms ағымдағы көрсетілген таңдаудың браузер көрініп тұрған уақытын ғана санайды. Қайта жүктеу жаңа decision instance жасайды. Бұл назар аудару не мәтінді түсіну өлшемі емес.

Өз сессиясының экспортын тек кіру кілті бар браузер ала алады. Зерттеушіге арналған барлық сессияны біріктіретін интерфейс бұл прототипте жоқ. Қазіргі сервер тек loopback интерфейсінде ашылады; сыртқа орналастырылмаған. Нақты жариялауда HTTPS, оператор рұқсаты, сақтау мерзімі/орны және backup-жою тәртібі бөлек бекітіледі.

Жою сессияны, оқиғаларды және retry жазбаларын транзакциялық байланыспен жояды; SQLite secure_delete және WAL checkpoint қолданылады. Бұл дискілік snapshot пен бұрын жүктелген экспорттарды автоматты жоймайды. Жүктелген файлды сынақшы өзі жояды.

CSV-де boolean true/false жолымен, null бос ұяшықпен беріледі. JSON типтері сақталады. events.csv payload бағаны JSON жолы ретінде қос тырнақшамен дұрыс экрандалады. Есім, байланыс, IP, геолокация, толық user agent, еркін мәтін, кіру кілті экспортта жоқ.

## 6. Шығару алдындағы келесі кезең

1. Автобус прототипін қолмен қарап, мәтін түсініктілігі мен нақты өту уақытын пилотта өлшеу; қиындықтарды тіркеу.
2. Саябақтың 6 бірліктік жоспар редакторын, содан соң аула мен орталықты сол серверлік журнал ережесімен қосу.
3. Нақты келісімдегі жауапты тұлға, байланыс, сақтау мерзімі/орны мен жою тәртібін бекіту.
4. Толық ойынның codebook/экспорт сәйкестігін тексеру, 1–2 пилот сессиясының нақты есебін жазу; одан кейін негізгі жинау.

Бұл кезеңде нақты 30/80 қатысушы, пилот нәтижесі немесе статистикалық әсер туралы тұжырым жоқ.
